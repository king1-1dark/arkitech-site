# Arkitech Studio — сайт (arkitech.studio)

Многостраничный статичный сайт студии разработки игр с академией, джемами, событиями и магазином (тестовый каркас). Хостинг — GitHub Pages (ветка `main`, корень репозитория).
Правки часто делаются с телефона через Claude Code, поэтому проект намеренно простой.

## Главные правила

1. **Только чистые HTML + CSS + ванильный JS.** Не добавлять сборщики, npm, `package.json`, фреймворки, препроцессоры, CDN-библиотеки. Единственная внешняя зависимость — Google Fonts.
2. **Сайт должен работать без сборки:** то, что лежит в репозитории, и есть сайт. После любой правки убедиться, что `index.html` открывается и в консоли нет ошибок.
3. **Все пути — относительные** (`css/style.css`, а не `/css/style.css`), чтобы сайт работал и на `arkitech.studio`, и на `*.github.io/arkitech-site/`.
4. **Ссылка на бота — только в `js/config.js`.** Не вписывать `t.me/...` в HTML.
5. **Цвета, шрифты, размеры — только через CSS-переменные** в начале `css/style.css`. Не хардкодить новые цвета в правилах.
6. Mobile-first: сначала проверять ширину 375px, потом ПК. Анимации — только `transform`/`opacity`; уважать `prefers-reduced-motion`.
7. Не удалять и не переименовывать `CNAME` (в нём домен `arkitech.studio`).

## Структура

```
index.html            главная: студия + блок «Направления», события, отзывы, вопросы
academy.html          академия: форматы, каталог программ с фильтрами, менторы, вопросы
program.html?id=КОД   страница программы (рисуется из data/programs.js)
jams.html             джемы и кэмпы: как работает запись, наборы со статусами, архив
jam.html?id=КОД       страница джема/кэмпа (из data/jams.js)
events.html           календарь событий: ближайшие / прошедшие
shop.html             магазин: каталог, корзина, заказ через менеджера
docs.html             оферта, политика ПДн, возврат, реквизиты (заглушки)
css/style.css         стили; в начале — :root с переменными
js/config.js          НАСТРОЙКИ: бот, платформа, оплата, приём заявок, таблица, Метрика, слои
js/layout.js          общие шапка (меню — массив NAV), подвал, окна, формы заявок, оплата
js/pages.js           карточки и страницы из данных data/*.js, фильтры, корзина
js/main.js            бот-кнопки, параллакс, меню, появление блоков, плавающая кнопка
data/*.js             ДАННЫЕ: programs, mentors, jams, events, products
assets/layers/        слои параллакса: bg, far, mid, fg, particles
assets/img/           обложки игр (game-1…4), og.png, apple-touch-icon.png
favicon.svg / CNAME   иконка / домен для GitHub Pages
.claude/serve.js      локальный сервер для проверки (не часть сайта)
```

Порядок скриптов на каждой странице важен: `config.js` → `data/*.js` → `layout.js` → `pages.js` → `main.js`.
Шапка и подвал не пишутся в HTML: на странице стоят пустые `<header id="header">` и `<footer id="footer">`, их заполняет `layout.js`.
Каждая страница — `<body data-page="…">` (подсвечивает пункт меню).

## Где что менять

| Что | Где |
|---|---|
| Пункты меню | `js/layout.js` → `NAV` |
| Программы академии | `data/programs.js` (`ready: false` — «Скоро», оплата закрыта) |
| Менторы | `data/mentors.js`; фото — `assets/img/mentors/` |
| Джемы/кэмпы, их статус и места | `data/jams.js` (`status`, `seatsLeft`) или Google-таблица (`SHEETS.jams`) |
| События | `data/events.js` (прошедшие уходят в архив сами по дате) |
| Товары | `data/products.js` |
| Тексты форм и «что будет дальше» | `js/layout.js` → `FORMS` |
| Ссылки: бот, вход, оплата, приём заявок | `js/config.js` |
| Тексты секций | соответствующий `*.html`, по комментариям секций |
| Цвета, шрифты, радиусы, отступы | `css/style.css`, блок `:root` |

### Как работают кнопки

| Атрибут | Что делает |
|---|---|
| `data-bot-link` | ссылка на `BOT_URL` |
| `data-platform-link` | вход на учебную платформу (`PLATFORM_URL`), пусто — окно-пояснение |
| `data-form="тип" data-item="код" data-title="…"` | окно заявки; типы — в `FORMS` (`pick-program`, `pick-mentor`, `jam-apply`, `jam-book`, `jam-wait`, `event-free`, `event-paid`, `order`, `notify`, `contact`) |
| `data-pay="код" data-format="self/feedback/personal"` | переход к оплате по шаблону `PAY_URL`, пусто — окно с шагами |

Заявки уходят POST-запросом на `FORM_ENDPOINT` (JSON). Пока он пуст — тестовый режим: заявка сохраняется в `localStorage` браузера (`arkitech_leads`). Токен Telegram-бота в коде сайта не хранить — нужен посредник (Cloudflare Worker и т.п.).

### Правила содержания

- Не выдумывать отзывы и не показывать искусственные счётчики мест: `seatsLeft` — только фактический остаток подтверждённого набора.
- Не принимать оплату за неготовую программу (`ready: false`) и за неподтверждённый кэмп (`status: "collecting"` — только заявка).
- Все оплаты — через сайт/платформу, без прямых оплат менторам.

### Кнопки бота

Любая ссылка с атрибутом `data-bot-link` автоматически получает `href` из `BOT_URL`, `target="_blank"` и `rel="noopener"`. Новая кнопка бота:

```html
<a class="btn btn--primary" data-bot-link href="#contact">Написать боту</a>
```

Плавающая кнопка `#fab` (создаёт `layout.js`) видна только на ширине < 768px: появляется после первого экрана и прячется у финального призыва.

## Параллакс и слои графики

Сцена — любой блок с `data-parallax`. Внутри — слои `<img class="layer" data-layer="имя" data-depth="…">`. Файл для каждого `data-layer` берётся из `LAYERS` в `js/config.js`.

- `data-depth`: `0` — бесконечно далеко (почти неподвижен), `1` — передний план, `>1` — ближе камеры (частицы). Текст тоже может быть слоем (`data-depth` на любом элементе).
- `data-strength` на сцене — множитель силы скролл-параллакса (у разделителей `0.4`).
- На ПК слои дополнительно сдвигаются за мышью; на телефоне — только скролл, сила меньше (`SCROLL_K` в `main.js`).
- Порядок слоёв в HTML = порядок наложения (нижний в коде — верхний на экране).

### Как заменить заглушки своей графикой

1. Положить файл в `assets/layers/` с тем же именем: `bg`, `far`, `mid`, `fg`, `particles`.
2. Если расширение другое (PNG/WebP вместо SVG) — поменять путь в `js/config.js` → `LAYERS`, например `bg: "assets/layers/bg.webp"`. Старый `.svg` удалить.
3. Требования к файлам:

| Слой | Содержимое | Прозрачность | Размер | Формат |
|---|---|---|---|---|
| `bg` | небо / космос | нет, заливка на весь кадр | 1920×1080 (лучше 2560×1440) | WebP / JPG |
| `far` | планета, дальние горы | да | 1920×1080+ | WebP / PNG с альфой |
| `mid` | город, силуэты | да | 1920×1080+ | WebP / PNG с альфой |
| `fg` | земля, передний план | да | 1920×1080+ | WebP / PNG с альфой |
| `particles` | частицы, искры | да | 1920×1080+ | WebP / PNG с альфой |

- Все слои — **одного размера и соотношения 16:9**, нарисованы на общем холсте, чтобы совпадали.
- Слои вписываются через `object-fit: cover` и **прижимаются к низу по центру**. На телефоне (вертикальный экран) видна только **центральная ~четверть по ширине** — важные детали держать в центре кадра (x ≈ 700–1200 из 1920).
- Слои показываются с запасом ~10–25% за пределами сцены, поэтому у нижнего края `fg` должна быть сплошная «земля» высотой не менее ~12% кадра.
- Вес: стараться < 300 КБ на слой (WebP, качество 80).

## Стиль

- Тёмная спокойная тема (графит), без неонового свечения: акценты `--accent` (янтарь), `--accent-2` (терракота), `--accent-3` (песок); основной градиент — `--grad`. Вместо свечения — мягкая тень `--shadow`.
- Шрифты: заголовки — Unbounded (`--font-display`), текст — Inter (`--font-body`). При смене шрифта обновить и `<link>` Google Fonts в `index.html`.
- Акцентное слово в заголовке: `<span class="grad">слово</span>`.
- Появление при скролле: класс `reveal` на блоке.
- Тексты — на русском.

## Проверка перед коммитом

```bash
node .claude/serve.js
```

Открыть `http://localhost:8123`, проверить все страницы: ширину 375px и ПК, консоль без ошибок, кнопки бота ведут на `BOT_URL`, мобильное меню открывается, окна заявок и оплаты открываются, нет горизонтальной прокрутки. Достаточно и просто открыть `index.html` двойным кликом — сайт работает и по `file://`.

## Публикация

`git push` в `main` — GitHub Pages обновит сайт сам за 1–2 минуты. Отдельного шага сборки нет.
